# Nova Haven World Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a responsive public map viewer built from the supplied Minecraft world save, with verifiable coordinates and markers.

**Architecture:** A dependency-free Python utility safely reads only Java `level.dat` and overworld MCA chunks and emits a small static terrain image/manifest. A Next.js server route supplies that data to an isolated client explorer; map controls and coordinate math remain in a pure tested helper. No backend, schema or CMS latitude/longitude changes.

**Tech Stack:** Python 3 standard library, Node 22 tests, Next.js 16 / React 19 / TypeScript, CSS.

**Spec:** `openspec/changes/add-world-map/specs/world-map/spec.md`; decision record `openspec/changes/add-world-map/design.md`.

## Global Constraints

- Read only the owner-supplied Java save; never copy the raw ZIP or player/entity/seed data into public assets.
- Minecraft coordinates are X/Z blocks; do not reuse Knowledge geographic latitude/longitude.
- Use the approved Nova Haven Master UI baseline; no generated art or Wynncraft-owned material.
- No API, SQL, plugin, deployment or Git-history changes are in scope.
- Do not claim verification unless the command/browser result was actually observed.

## Review Focus

- Malformed ZIP paths, oversized entries and invalid sector offsets must fail safely — Python renderer unit tests.
- Padded palette/heightmap storage, negative world coordinates and missing sections must decode correctly — Python unit tests.
- Selected map coordinates must stay correct under zoom and across negative X/Z — Node helper tests.
- Keyboard/focus and responsive layout have been directly inspected at 320×800, 390×844, 844×390 and desktop; no page-level horizontal overflow was observed.
- Missing image/manifest must not appear as real terrain — route empty-state test.
